# 分阶段排错与性能

用于定位现有问题；按已观察到的故障选择分支，不要求每次全量巡检。这里只组织证据与定位，游戏启动和操作遵循实际项目的验收入口。

## 从最早失败的边界查起

| 现象 | 先核对 | 下一份资料 |
| --- | --- | --- |
| 整个包不加载 | manifest/依赖、目标包体、目录、日志首个解析错误 | 工程结构/版本 |
| 内容不出现 | identifier、注册目录、格式/组件、原始资源是否可获取 | 物品/方块/实体 |
| 有对象但没外观 | BP/RP ID、图集/几何简称、材质、渲染控制器引用 | 渲染 |
| 动画/粒子不运行 | animate 接线、状态条件、变量环境、资源 ID 与实例句柄 | 动画/粒子 |
| UI 空白或点击无效 | _ui_defs、画布与类路径、就绪事件、控件路径/层级/输入 | UI |
| 只在重进/切维度后出错 | 重建时机、缓存失效、重复监听、存档/消息状态 | 状态同步 |
| 新地形不生效 | 是否新生成区块、维度/群系源、特征生成阶段 | 世界生成 |

文件检查只证明格式和引用完整；热更新 Python 成功不能证明 JSON/资源已重新加载。按修改类型选择目标环境支持的重载方式；不要用编辑器预览代替多人、存档和移动端行为验证。

## 性能定位原则

1. 先量化频率 × 对象数 × 每次成本；区分服务端逻辑/网络与客户端绘制/模拟。不要把所有 Tick 都假定为 20Hz：不同事件的频率依合同确定。
2. 先做廉价的类型/范围判断；以数据变化或合适频率触发工作。错峰与分批要能覆盖所有目标，避免把不同频率计数器混在一起取模导致漏执行。
3. 缓存组件/对象时同时记录绑定对象与失效条件；优化不能让跨世界、跨实体缓存继续使用。生命周期不清楚时先修归属，再讨论复用。
4. UI 列表、粒子数量、骨骼/材质批次和广播消息分别限量；文档案例中的固定数字不是所有设备的预算。减少不需要的创建、重建、日志和广播。
5. 实机选择本次变化的核心操作与必要边界：重复打开/关闭、重连、区块重载、多人并发或较低性能设备。记录现象、相关日志及已核验合同，保留最小有效证据。

## 按实际失败层定位

资源解析、引用和数据驱动运行使用共享的排错逻辑；只有故障涉及网易目录、Python 生命周期或专用模型时才追加对应诊断。先修首个根因，并在真正消费资源的入口观察结果；不因对象运行在中国版就假定必须换成专用实现。
