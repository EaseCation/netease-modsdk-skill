# 目标版本与证据边界

用于跨版迁移、格式选择或来源冲突；同一任务确认后保留结论，不每次重新加载。

本套开发目标按用户提供的中国版包体对应 **BE 1.21.130**。查询库自述为 **ModSDK 3.9 / BE 1.21.120 文档快照**；这是资料的版本，不覆盖用户项目实际包体信息，也不能证明 1.21.130 新字段都已接入网易扩展格式。实施前记录包体版本、端侧、目标平台、实验开关和项目采用的格式路线。

## 四种版本不能混为一谈

| 信息 | 作用 | 常见误判 |
| --- | --- | --- |
| 中国版客户端/服务端包体 | 决定实际运行环境 | 仅凭一个基岩版本号推导所有网易能力 |
| ModSDK 文档快照 | 给 Python API/事件合同的证据 | 把旧快照没有记载当成平台永久不支持 |
| manifest min_engine_version | 声明包的最低引擎要求并影响部分行为 | 把它改大就认为功能已解锁 |
| 每个 JSON 的 format_version | 选择该文件的语法/行为合同 | 全项目统一替换成 1.21.130 |

共享引擎机制值得优先复用，但必须核对 **注册目录、解析器、字段版本、实验开关、查询环境、渲染后端、发布平台限制**。已有实机结果只覆盖观察过的包体/路径，不概括其他端。

## 选型与比较原则

先尝试目标包体可用的原版共享 JSON、资源机制与接口。能满足需求就沿用；仅在能力不足时引入网易组件、专用格式或 Python 扩展，并指明它补足的职责。版本证据不足时先核验原版路线，不自动把“不确定”解释成必须使用专用实现。

按具体能力和格式比较，不能按国别虚构整个对象体系。实体行为/RP 实体、Molang、原版动画及控制器是共享机制；网易专用模型系统、独有组件和 loader 才是需要区分的扩展点。使用网易模型不意味着实体行为也被换成“网易实体”。

标记证据为：共享且已核验、网易扩展、有条件（格式/实验/上下文/后端）、未核准。未核准项保留待查，既不编造支持，也不因此排除整个模块。只有存在实际分叉时列比较表，共享机制用一套流程说明。

优先目标包体的资源与实测记录、对应版本官方说明，再用教程解释机制。Wiki 的中文 Bedrock 镜像含旧译与历史实验内容；固定到 2025-12 的国际版文章也可能有更早的过时章节，按页检查。不得复制镜像中“全部失效”“一定在未来失效”等推测作为当前中国版结论。

国际版块/物品格式参考固定 Bedrock Wiki 提交 `883d8638924820e4a7cc8783ef4d0d983243afd1`，该快照相关页面明确面向 1.21.130；Molang 数学及群系补充用官方文档提交 `b9b196e3c9fa05e7c742d07086ebe77fd4ad37fe`。它们是可复现资料，不是中国版兼容认证。遇 1.21.130 新能力，需额外核验目标包体。
