# 自定义维度

先区分“注册一个独立世界空间”“改变已有维度的环境”“改变群系/地形”。三者不能用一个传送接口代替。

## 网易路线

1. 项目固定一个不冲突的维度 ID。原生维度为 0–2；旧项目可能使用 3–20。新声明按文档使用 22–2147483647 范围内的 ID，不在每次启动时重新随机分配。
2. 新定义放 `BP/netease_dimension/dm<ID>.json`，根为 `format_version: "1.14.0"` 和 `netease:dimension_info.components`，components 即使空也要保留。原生维度配置采用文档指定文件名，不按新 ID 文件名照搬。
3. 按目标选择 `netease:dimension_type` 与 noise/flat/legacy 生成器。某些生成器仅支持指定维度类型，且不能用于改造原生维度；禁止原版结构/特征是独立选项。
4. 群系和出生配置需与该维度对应。3.9 更新说明要求 `biome_type` 填完整命名空间 identifier，旧教程省略命名空间的示例不能直接沿用。需要完整地形时再读 [世界生成](worldgen.md)。
5. 注册资源后，再查切维度、目标区块就绪、目标位置及返回点等 Python 职责。切换开始/完成事件都保留，只有对应完成时机才执行依赖新维度状态的操作；客户端 UI/效果可能重新初始化。
6. 生成参数主要影响新生成的区块。旧维度存档与新参数可能产生接缝；文档中的 `UpgradeMapDimensionVersion` 会废弃原维度存档信息，不把它当常规刷新/清理步骤。
7. 实机观察首次进入、重进、退出重启、往返、出生/重生、多人处于不同维度及与其他组件的 ID 冲突。环境视觉、群系选择和实际方块分别核对。

## 路线对比

| 能力 | 中国版网易路线 | 国际版 1.21.130 数据包范围 | 限制 |
| --- | --- | --- | --- |
| 新增独立维度 ID | 有 `netease_dimension` 声明及 Python 切换能力 | 本套目标资料未核准等价的标准新增维度注册路线 | 不把已有维度配置或群系替换当作新维度 |
| 生成器选择 | noise/flat/legacy 等网易组件 | 使用其已有世界生成机制 | 网易字段不直接移植 |
| 群系/环境改造 | 自定义维度关联群系与客户端环境 | 群系覆盖、实验性部分替换及客户端环境定义 | 改环境不产生独立坐标/存档空间 |
| 大型结构、传送门 | 网易专门数据配置与接口 | 标准数据机制各自核验 | 外观相同不证明两套结构池/传送规则等价 |

“未核准”是本套证据边界，不是把所有未来版本或平台实现判为不支持。
