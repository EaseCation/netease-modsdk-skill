# 通信、状态与生命周期

用于多端状态不一致、重复操作、重进丢数据或资源未释放。以下是工程建议；具体消息、存储和生命周期合同仍用 query 核验。

## 先定义状态的归属

| 状态 | 建议拥有者 | 生命周期 |
| --- | --- | --- |
| 规则结果、库存、持久化业务数据 | 服务端及选定的存储对象 | 按玩家/实体/世界的实际持久化合同 |
| UI 展示、镜头、粒子句柄 | 对应客户端 | 界面、实体或场景退出时释放 |
| 双端共享配置 | 无端侧依赖的配置模块 | 随组件版本加载 |
| 动画中间值、临时缓存 | 使用它的运行实例 | 不默认保存、不默认跨端同步 |

1. 先给每项数据定义主键、单位、缺省值和拥有者。运行期 entityId 不直接当永久玩家账号；存档、世界、玩家、客户端本地配置的保存范围分别核验。
2. 消息包含任务所需的最小字段、操作标识和结果版本。客户端发意图，服务端从可信上下文确认身份并复核目标与条件；避免重复点击、迟到回复或事件重入重复执行同一操作。
3. 初始化使用明确的状态快照，之后按需发变化；只给需要的玩家发送。必要时用序号识别过期响应。不要把全部世界状态每帧广播。
4. 区分“事件总线监听命名空间”“引擎事件”“自定义双端消息”。监听对象、回调和注销参数成对保存；不要把监听本地事件当成已跨网同步。
5. 加载顺序分别确认：System 就绪、玩家进入、实体可用、UI 初始化、维度完成、区块可访问。不能用固定延迟冒充这些就绪条件。前/后阶段可并列查阅，但依赖状态只能在正确阶段使用。
6. 持久化数据带最小 schema 版本，明确缺省与迁移；临时句柄不序列化。先识别真实保存接口及保存时机，避免把任意 Python 字典/客户端本地文件当成服务端持久化。
7. 按拥有者解除监听、取消定时器、销毁效果/UI、清理实体缓存。重载与重新连接应能恢复必需状态，而不是依赖上一次进程内存。

## 路线对比

| 能力 | 中国版 | 国际版数据驱动 | 边界 |
| --- | --- | --- | --- |
| 双端 Python 消息 | System 的定向/广播通知接口 | 无同名网易 Python 总线 | 不将本地事件广播当网络协议 |
| 表现读取状态 | 消息、实体属性及客户端节点 | 数据驱动属性与可用查询 | property 的 client_sync 与普通变量不同 |
| 保存数据 | 选定 ModSDK 存储能力，按对象范围核验 | 已声明对象状态按引擎机制处理 | 无法据同名“属性”证明保存、同步和卸载语义相同 |
