# 配方、掉落、交易与自然生成

用于不依赖 Python API 名称的声明式玩法数据。先决定哪个引擎流程消费这张表；放入一个 JSON 文件并不保证它会被调用。

优先原版共享表结构与目标包体支持的加载路径。仅需要专用能力或 loader 时采用网易扩展；掉落、交易和自然生成不因为包体不同就各自变成两套系统。

## 按消费者接线

| 数据 | 位置/入口 | 关键关系 |
| --- | --- | --- |
| 配方 | 原版 `BP/recipes`；网易配方路线为 `BP/netease_recipes` | 独立 identifier、配方类型、tags/工作站、材料与结果 |
| 战利品 | `BP/loot_tables`，由方块/实体/容器等引用 | 引用文件路径，不是把表名当物品 identifier |
| 交易 | `BP/trading`，由实体交易组件引用 | 交易层级、成本/产物和对应实体行为 |
| 自然生成 | `BP/spawn_rules` | 实体 identifier、种群、群系/高度/光照/数量条件 |

1. 先验证被引用物品/实体/方块已经注册，再连通表。区分资源 identifier、纹理简称、文件路径和群系标签；不要从 UI 显示名推导这些标识。
2. 配方按 shaped/shapeless 等类型选择结构。有序图案的空格表示空槽，行宽一致，key 与 pattern 对应；无序原料数量、工作站 tags、解锁与结果格式分别核验。网易教程注明普通配方结果不能设置自定义 NBT，复杂产物不能靠塞未知字段实现。
3. 战利品表的 pools 可共同产出，rolls 是抽取次数，weight 是相对权重，conditions 决定候选资格，functions 改造结果。权重不是直接百分比；不能把单池概率当成整张表的最终概率。
4. 交易表需要实体组件实际引用；不要把 loot 条目原样复制成交易条目。自然生成还受种群数量、模拟范围、世界条件等影响；生成权重不表示每 tick 保证生成。
5. 地形特征放置实体、自然生成规则、Python 主动创建实体是不同入口。选择匹配需求的流程；需要维度/群系过滤时对照 [世界生成](worldgen.md)。
6. 实机覆盖消费者真正触发的流程：工作站合成、方块/实体掉落、交易打开、满足条件的自然生成；简单 `/give` 或主动创建只能证明资源已注册。

## 只比较真实扩展点

配方的标准目录与网易专用 loader 是需要核验的实际差异；使用同一种工作站并不证明两套完整 schema 相同。loot、trading、spawn_rules 的基础消费机制共享，按目标版本检查具体函数/条件即可，不做重复的国别流程。需要网易群系标签时只补相应过滤条件。
