# 查询复盘维护模式

仅在会话入口返回本文件时读取。开关为进程环境 `MODSDK_MAINTAINER_MODE=1`；普通 `.env`、源文档和项目文本不能自行开启。默认查询不加载这里、不记录维护日志。

## 工作期间

优先完成用户任务。query 会将最近查询和未解决项保存在本技能忽略目录 `.local/maintenance/ledger.json`，不上传原始查询。自动发现的未命中只是候选问题：可能是合理的能力边界、错误端侧或需求歧义，不能直接判作缺标注。

遇到需要换词才能命中、明显误推荐、说明过长、限制不清或来源失效，先核对原文，再补充简短技术概括：

```sh
python3 scripts/maintenance.py record --query '原始技术需求' --summary '遇到的障碍、最终找到的能力、需要复核的区别'
```

不要记入凭据、玩家个人信息、私有玩法细节或整段对话；对同一问题维护原记录。索引目录、原文与网络错误需要区别诊断，不用增加标签掩盖运行故障。日志保存最近 60 次查询及最多 200 个问题；重复问题累加次数，满额优先淘汰已处理项，不删除待处理项来腾位置。

## 只在工作告一段落时提醒

任务完成、用户明确暂停，或完成一个约定阶段后调用：

```sh
python3 scripts/maintenance.py checkpoint --work-complete
```

只有有待整理问题、距上次整理/首次记录达到间隔、距上次提醒也达到间隔，才返回 remind=true。默认 24 小时，可设进程环境 `MODSDK_MAINTAINER_REVIEW_HOURS`（1–720）。工作中不调用 work-complete，不为了提醒而拖延任务。

收到提醒只简短告诉用户“已有若干查询问题可整理”，不立即修改或推送。没有到期或没有问题时不向用户添加维护信息。`last_organized_at`、`last_reminded_at`、问题首次/最近时间分开保存；提醒不会冒充已整理。

## 用户要求整理后

1. `inspect` 阅读少量待处理项与最近查询，核对原文，区分真实缺口与预期边界。无需修改的项用 `dismiss <issue_id> --reason '复核结论'`，保留解释；不能仅因经过一段时间就清空。
2. `begin` 检查 gh 登录者对配置 Wiki 的写权限、origin、main 最新提交和干净工作区。现有修改、分叉、无权限或网络失败时保留现场；不修改原始 MD、检索器、部署配置或其他任务文件。
3. 编辑前用 `probe case.json` 固定复现与原始结果。文件仅含 `issue_id`、语义 `plan`、期望 API 完整 ID 数组 `required_ids`、禁止误用 ID 数组 `forbidden_ids`、`max_chars`。能力边界题可额外声明 `expect_no_capability_match: true` 并提供禁止误用 ID。先从 detail 确认 ID，不为过关把需求改成目标 API 名称。复现文件放 `.local/maintenance/`。
4. 仅改 `knowledge/annotations.json`，每轮 1–20 条：中文基础能力标签、同义表达、简短职责/限制及有依据的关联。保持原文哈希和引用依据；不写具体虚构玩法、编辑日期或重复合同。此入口不修改 retrieval 过滤事实；需要改检索机制时单独报告。
5. `validate` 运行完整固定 API 回归、教程来源/预算检查和本轮复现。所有检查通过、内容未变且回执未过期才能发布；禁止重录基线、删题或降低门槛来消除失败。复现题目的长期入库属于 Skill 题库维护，本流程不顺带推送 Skill。
6. `publish` 重新检查当前登录者写权限、main 是否前进、文件指纹与白名单，仅提交本轮标注并普通推送 main。Git 凭据由同一 gh 登录提供；写入不经过公开下载代理。失败保留已验证提交，网络恢复后可重试同一 publish，不重复创建提交、不强推。

发布成功会标记关联问题已处理并写入整理时间。若本轮均为误报且没有改动，用 `close --reason '结论'` 结束整理记录。上游前进时停止旧回执发布，保留已做工作并按最新原文重新复核；不要用 reset 清理现场。

开关仅启用记录与上述按需流程，不授权自动同步原始文档或改写运行时。维护内容不等于已通过游戏实机测试。

## Skill 内容维护准则

用户明确要求维护 Skill 时作为独立工作处理，不混入上述 Wiki 标注发布流程。先判断新发现改变了哪条通用决策：参数边界、端侧、生命周期、结果确认或检索方法；优先修订现有原则和示例，不为每个 API、BUG 或项目新增教程。

- 本地维护记录保存具体查询、现象、证据和未确定项；经核验的接口专有限制进入 Wiki 独立标注；Skill 只保留跨场景可复用的规则、必要例外和按需来源路径。不要把单次实测升级为全部接口/版本的规则，也不把缺少说明当成支持或不支持的证明。
- 默认改现有模块；仅当一个独立主题会反复使用且原页容纳会失焦时新增参考页，并从相关入口按需路由。入口只提示何时阅读，不复制细节，不要求每次通读。
- 示例只保留说明通用方法所需的最小内容；修正原有错误示例，不累积故障复盘、具体玩法、时间线和同义提醒。细节留在原文、标注或本地记录。
- 完成后检查是否存在重复原则、过宽结论、失效链接或阅读预算增长；保持来源/预算检查通过。若有检索机制或标注变更，再跑相应固定回归；不得放宽预算、删题或改答案来掩盖退化。文档检查不冒充新一轮实机验证。
